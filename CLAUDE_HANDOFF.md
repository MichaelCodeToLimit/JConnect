## 1. What JConnect is

JConnect ("Just Connect. Open. Connect. Work.") is a remote-desktop app built from the owner's spec, *JConnect full description*. It includes:

- **Pairing and connecting:** pairing with a 6-digit code or QR code, trusted and family devices, Wake-on-LAN and automatic reconnection.
- **Security:** Travel Mode and Emergency Lockdown.
- **Networks:** JVPN (its own relay network), plus Tailscale, Twingate, ZeroTier, WireGuard and Windows VPN, with machine import.
- **Tools:** an SSH terminal and Remote Desktop (RDP).
- **Account:** optional, with end-to-end encrypted sync.
- **Browser access:** phones, tablets and TVs use JConnect in the browser.

## 3. The app (`C:\Users\micha\Jconnect`)

**Stack:** Electron 38.8.6 and electron-builder 26.15.3, with Node 24 locally. Windows use context isolation and the sandbox, and the packaged app has Electron fuses set.

**Layout:**

- `src/main/`: the main process.
  - Core: `main.js` (wiring, `jc:*` IPC, tray, Mac menus and permissions), `host.js` (host agent, protocol v2), `store.js`, `security.js` (lockdown levels), `resources.js`.
  - Networking: `discovery.js` (TCP 47801, UDP 47802), `capture-bridge.js`, `jvpn.js`, `account.js`, `routes.js`, `vpn/*`.
  - Tools: `ssh.js`, `rdp.js`, `shortcuts.js`, `selftest.js`.
  - Input: `input/` holds `index`, `windows` with `win-input.ps1`, `mac`, `nut` and `keymap`.
- `src/shared/`: `secure-channel.js` (X25519, XSalsa20-Poly1305, Ed25519 identities, scrypt proofs), `protocol.js`, `viewer.js`.
- `src/renderer/`: the app, session, capture and terminal windows. `src/web/` is the browser client for phones and TVs.
- `server/cloud/cloud.js`: JConnect Cloud (accounts, vault sync, devices, relay tickets, TOTP, TURN). It stores data in `server/cloud/data/cloud.json` and listens on port 47900. The relay is `server/relay/relay.js`.
- `native/mac-input.swift`: the macOS input helper (CoreGraphics events). `scripts/build-mac-input.js` builds it as a universal binary and ad-hoc signs it.
- `build/JConnect.icon`: the Mac app icon, an Icon Composer (Liquid Glass) document. Also `build/entitlements.mac.plist`.
- `assets/`: icons generated by `scripts/make-icons.js` (`icon.png`, `icon-mac.png`, `tray*.png`, `trayTemplate*.png`).
- `.github/workflows/mac.yml` and `release-windows.yml`, plus release notes in `.github/releases/`.
- `server/cloud/supabase/migrations/20260911083000_jconnect_accounts.sql`: the accounts schema (see section 6).

**Commands:**

```bash
npm start                  # run JConnect
npm run start:b            # second copy with its own identity
npm run dist:win           # dist/JConnect-Setup-0.1.0.exe and the portable exe
```

## 6. Supabase accounts database (written and tested, not yet applied)

**The migration** (`server/cloud/supabase/migrations/20260911083000_jconnect_accounts.sql`) creates a `jconnect` schema that Supabase's public API doesn't expose. It holds four tables, all with row level security on:

| Table | Holds |
| --- | --- |
| `accounts` | Email, KDF salt, auth verifier (`serverSalt:hash`), TOTP, and the vault blob and version |
| `devices` | Each device's Ed25519 public key; at most 50 per account, enforced by a trigger |
| `sessions` | SHA-256 token hashes with an expiry |
| `settings` | One row with `prelogin_secret` |

`anon` and `authenticated` have no access, and `service_role` is granted. The migration also adds format checks and `purge_expired_sessions()`.

**Testing:** on an in-memory Postgres (PGlite 0.5.8) it passed all 21 checks: constraints, the device limit, vault versioning, cascades and privileges.

- **Commit identity:** always use `git -c user.name="Michael Davies" -c user.email="205437504+MichaelCodeToLimit@users.noreply.github.com"`, because GitHub email privacy rejects the personal address.
