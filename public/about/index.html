About the project

About JConnect

JConnect is a remote-device app for Windows, macOS, Linux and Android, built around one idea: remote access should be as easy as using a computer normally. This page is the reference account of what it is, how it works and where it stands.

Overview

What JConnect is

JConnect is remote-desktop and remote-access software that lets someone use one of their own computers from another computer, a phone, a tablet or a television. It was designed so that the everyday case — reaching your own machines — needs no network knowledge at all: there are no IP addresses to find, no ports to forward, no VPN profile to configure and no account to create. Two computers on the same network discover each other automatically; the user pairs them once with a six-digit code and presses Connect.

The name is short for Just Connect, which is also the project’s design rule: any feature that would require the user to understand networking before it works is considered unfinished.

Beyond screen sharing and remote control, JConnect includes an SSH client, Remote Desktop (RDP) routing, an optional encrypted account with device sync, and JVPN — its own relay network for reaching machines away from home without installing a separate VPN. It can also drive VPNs the user already has, including Tailscale, Twingate, ZeroTier, WireGuard, FortiClient and Windows VPN connections.

History

History

JConnect was started on 10 September 2026 by Michael Davies, an independent developer. The first working version paired two Windows computers over a local network and shared one screen with the other.

Development moved quickly across platforms in the days that followed:

  • The desktop agent, browser client and relay, followed by the Windows installer.
  • Encrypted protocol v2, JVPN, accounts with sync, the VPN integrations and SSH.
  • The macOS build, with a Swift input helper, permission handling and a menu-bar presence. Its DMGs are built on CI, because they need Apple’s own tools.
  • Linux packages (.deb and AppImage) with a C input helper for X11, built on an older base so they also run on older distributions.
  • The Android app, a Capacitor wrapper around the browser client, extended for Android TV and Google TV so a television becomes a remote-control client.

The first public builds were released as version 0.1.0 beta through the project’s own website rather than through app stores. As of this writing the software is an early beta: it is usable day to day, but the Windows and macOS builds are not yet code-signed or notarized, and several features listed below are incomplete.

How it works

How it works

Discovery and pairing

A computer running JConnect announces only a name and a public key on the local network, and that announcement can be turned off. Another device shows those computers under Add Computer. Pairing happens once, in one of two ways: the user types the six-digit code shown on the other computer, or chooses Ask for permission, in which case someone at the other machine confirms that both screens show the same verification code. After pairing, the computer recognises the device by its key.

Identity instead of addresses

Every device holds an Ed25519 identity key, and its device ID is derived from that key. Because identity is a key rather than an address, the same paired relationship keeps working when a machine moves between networks, changes IP address or is reached through a relay — which is what removes address and port configuration from the user’s side of the problem.

Connections

Control data — input events, SSH traffic and RDP traffic — travels over JConnect protocol v2, an encrypted channel described below. Screen and sound travel over WebRTC, which is itself DTLS-SRTP encrypted, with its keys signed inside the protocol v2 channel so they cannot be substituted.

Getting there

On a local network, devices connect directly. Away from home, JVPN carries the connection: each computer keeps an outbound, signed connection to a JConnect Cloud relay, and the user’s other devices dial it through that relay using a one-minute ticket. The relay passes encrypted bytes only — it cannot read, alter or impersonate a connection — and only devices registered to the same account can see or dial each other. JVPN installs no system-wide network adapter, so other applications on the machine do not see it as a VPN.

Where a user already runs a private network, JConnect can use that instead. It starts the VPN when needed, asking for administrator permission only where the VPN itself requires it, imports the machines on it, checks what each one offers (JConnect, SSH or Remote Desktop), and never modifies the VPN’s own settings.

Security

Security model

Every connection uses JConnect protocol v2 regardless of which network carries it.

  • End-to-end encryption. Each connection performs an ephemeral X25519 key exchange, after which messages are sealed with XSalsa20-Poly1305. Frames are numbered, so altered, replayed or reordered data closes the connection.
  • Mutual authentication. The computer signs the connection’s transcript with its Ed25519 identity key and the connecting device checks it against the key it paired with; the connecting device signs the same transcript, so a captured message cannot be reused elsewhere.
  • Secrets stay local. Pairing codes and passwords never cross the network. They are turned into scrypt proofs bound to a single connection, so an eavesdropper learns nothing reusable.
  • Keys at rest. Device keys, API keys, account tokens and SSH keys are encrypted with the operating system’s key store — DPAPI on Windows, the Keychain on macOS.
  • Account data. The account password never leaves the device. It is stretched into two keys: one the server verifies, and one that encrypts synced data before upload, so the server stores ciphertext it cannot open. A forgotten password therefore cannot be recovered. Two-step sign-in with an authenticator app is supported.
  • Reduced surface. Discovery can be disabled, windows receive only the permissions they need, and the packaged application ships with Electron fuses set: no Node integration, no inspector, and asar integrity checking.
  • Travel Mode and Emergency Lockdown restrict or sever access across every path, JVPN included.

Under the hood

Architecture

The desktop application is built on Electron. Its main process holds the host agent that shares the machine, the JVPN client, account and sync, the VPN integrations, routing and the SSH client, along with input injection, the tray and window management. A shared layer implements the v2 secure channel, the client protocol and the remote-desktop viewer, and is used by every client — desktop, browser and mobile — so all three speak the same protocol.

Input injection needs native code on two platforms: a Swift helper on macOS and a C helper using X11 and XTest on Linux. The Linux helper is compiled on an older base so the packages also run on older distributions.

The browser client serves phones, tablets and televisions. The Android app is a Capacitor wrapper around it, adding QR scanning, network discovery, adding computers by address, television detection and back-button handling.

JConnect Cloud is a Node.js server providing accounts, encrypted sync, the JVPN relay and TURN. It stores data in SQLite by default, or in PostgreSQL — including Supabase — and users can run their own instance rather than relying on one operated by the project.

Cryptography uses TweetNaCl (X25519, Ed25519, XSalsa20-Poly1305) with scrypt for password and pairing-code proofs; SSH uses ssh2, with xterm.js as the terminal.

Design

Design decisions

Several choices distinguish JConnect from other remote-access tools, and each carries a cost worth stating plainly.

No account required

Local connections and pairing work with no sign-up at all, and an account is needed only for reaching machines away from home and for syncing device lists. The cost is that the convenience people expect from commercial tools — a device list that follows you everywhere — arrives only when a user chooses to create one.

No system-wide VPN

JVPN is built into the application rather than installed as a network adapter, so it does not change how other applications see the network, and it does not require administrator rights to run. The cost is that JVPN carries only what JConnect carries: remote desktop, SSH and RDP to JConnect computers, not arbitrary traffic.

A self-hostable server

The relay, account server and sync store are a single Node.js application anyone can run, against SQLite or PostgreSQL. A user who does not want to depend on infrastructure operated by the project is not required to.

The television as a first-class client

Rather than treating a TV as a large phone, the Android build detects televisions and switches to a layout designed for a directional remote. This is unusual among remote-desktop applications and was a deliberate target rather than a side effect.

Status

Status and known limits

JConnect is an early beta, and the project states its limits rather than working around them:

  • The Windows build is not code-signed, so SmartScreen warns on first run. The macOS build is not notarized, so macOS asks the user to confirm it.
  • Windows cannot be controlled on the secure desktop — UAC prompts, Ctrl+Alt+Del and the lock screen. Applications running as administrator ignore input unless JConnect also runs as administrator.
  • Linux computers can be controlled only in X11 sessions. Wayland control is not implemented and screen sharing there is untested.
  • A Mac cannot be controlled at its lock screen or login window, and its sound is not shared yet.
  • The browser client for phones is served over plain HTTP on the local network. The connection itself is still end-to-end encrypted, but the desktop app is recommended on untrusted networks.
  • The Android app is signed with a development key and is not distributed through Google Play.
  • Camera sharing is described in the project’s vision but is not built.

Updates are delivered from the project’s own website: the application checks for a new version every few hours and verifies that a download matches the exact size and SHA-256 the site publishes before installing anything.

Licensing

Licensing and the name

JConnect is proprietary software. Its source code is not public, and the builds offered on this site are free to download and use during the beta.

The name is not unique. Unrelated products and organisations also use “JConnect”, including a professional networking organisation and unrelated mobile applications; there is no connection between them and this project. Where ambiguity matters, this software is JConnect — Just Connect, the remote-device application described on this page.
